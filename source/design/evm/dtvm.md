# DTVM 总结

## 1. DTVM

DTVMStack 开源项目，主要包含：
- 一个虚拟机：**dtvm**
- 两种合约编写工具：C++ 和 Solidity

### 1.1 dtvm

dtvm 的基础是一个 Wasm 虚拟机，在此基础上进行了大量**扩展与优化**，并能够支持 EVM。

**dtvm 新特性：**

- 具有增强性能的**确定性 JIT 执行引擎**
- 实现特定于区块链的**确定性中间表示（dMIR）**，确保执行完全确定性
- 提供模块化适配层，将不同指令集（Wasm、EVM 及未来可能的 RISC-V）转换为统一的 dMIR
- 采用**混合惰性 JIT 编译引擎**，支持动态优化级别（O0~O2），在编译效率与执行速度之间取得平衡
- **EVM ABI 兼容性**与多语言生态系统支持
  - 保持与最新 Solidity 0.8.x 规范兼容
  - 同时支持六种编程语言：Solidity、C/C++、Rust、Java、Golang、AssemblyScript
  - 提供以太坊 ABI 兼容，可与现有以太坊生态无缝集成
- **TEE 原生安全性**与硬件优化效率
  - 通过最小化的可信计算，为 Intel SGX 等应用级 TEE 提供高可移植性
  - 与其他 Wasm 实现相比，代码库与二进制体积更小，减少潜在攻击面

**SmartCogent**：人工智能驱动的智能合约开发与审计
- 集成代码生成、安全审计、自动修复工作流
- 大幅提高开发效率与合约安全性

### 1.2 geno

- 虚拟机：原生使用 **wasmtime**
- 运行模式：**AOT**（提前编译）
- 合约语言：可扩展（理论上支持多种语言，但需要重新开发配套合约工具）
- 业界也有不少 Wasm + TEE 结合的方案

### 1.3 DTVM 特性对比分析

#### 性能分析

- AOT 与 JIT 本身并无绝对优劣，性能差距主要取决于**优化深度**
- wasmtime：通用型 Wasm 虚拟机，应用领域广泛
- dtvm：专为区块链领域深度定制，优化更深入，性能表现更好
- 次要原因：dtvm 使用业界成熟的 **LLVM** 作为编译后端，而 wasmtime 使用自研的 **Cranelift**（目前仍在快速发展中，性能相对较弱）

#### 合约语言支持

- Wasm 原生支持多语言，但区块链场景下需额外开发大量配套工具（账户、余额、区块高度、事件等接口）
- 每增加一种语言都需要独立开发一套工具链，成本很高
- dtvm 当前已开源：**C++** 与 **Solidity**

#### TEE & AI

- TEE：硬件可信计算方案，与具体硬件强相关，当前暂不深入考虑
- AI：符合当前趋势，作为开发者辅助工具（集成 OpenAI、Claude 等），可显著提升开发效率与安全性

#### dtvm 未来规划

1. 通过原生支持密码学原语与硬件加速指令，进一步增强 dMIR 中间层
2. 扩展 JIT 后端兼容性，支持更多新兴 CPU 架构，同时保持执行确定性
   - EVM 字节码支持
   - RISC-V 指令集支持
3. 开发零知识友好型虚拟机变体，集成对 zk-SNARK 友好的特性支持

## 2. 合约语言 SDK

### 2.1 C++

**DTVM_CppSDK**  
用于在区块链上以 C++ 开发智能合约的 SDK，属于 DTVM 生态一部分。  
开发者可使用 C++ 编写合约，编译为 WebAssembly (WASM) 字节码，部署在兼容 EVM 的 Wasm 合约链上。

### 2.2 Solidity（开发中）

**DTVM_SolSDK**  
一个开源编译器，使以太坊 Solidity 智能合约能在基于 Wasm 的区块链上运行。  
工作方式：接受 Solidity 的 **Yul 中间表示（IR）** → 转换为优化的 WebAssembly 字节码  
保持与以太坊智能合约模型的兼容性，保留原始合约逻辑与行为。

### 2.3 geno

- 开发语言：**Rust**
- 采用 Rust 自研的 **eDSL**（嵌入式领域特定语言）
- 可与系统合约、链上资产等功能良好配合使用

## 3. 移植难度分析

DTVM 使用 **C++** 实现，而本项目基于 **Rust**，直接移植有一定难度。  
目前较可行的方案：采用 **FFI**（外部函数接口）

### 3.1 关于 FFI

- Rust 支持通过 FFI 调用使用 **C ABI** 编译的外部函数/库
- C++ 因缺乏统一 ABI，无法直接使用 `extern "C++"`
- 常见做法：
  1. 在 C++ 侧使用 `extern "C"` 包装函数（避免 name mangling）
  2. 或使用工具自动生成绑定

### 3.2 移植后的合约语言

移植完成后，可直接使用 DTVM 官方提供的  
→ **C++** 合约开发  
→ **Solidity** 合约开发

## 4. 性能测试对比

测试内容：分别使用 DTVM 与 Wasmtime 执行斐波那契函数 `fib(6)`，循环执行 100 次

| 项目          | 第一轮                  | 第二轮                  | 第三轮                  |
|---------------|--------------------------|--------------------------|--------------------------|
| **Wasmtime**  | 平均：51.918µs<br>最慢：117.645µs<br>最快：44.314µs | 平均：66.604µs<br>最慢：427.097µs<br>最快：47.592µs | 平均：68.889µs<br>最慢：1.14994ms<br>最快：45.832µs |
| **DTVM**      | 平均：32.937µs<br>最慢：1.110703ms<br>最快：13.444µs | 平均：38.137µs<br>最慢：1.07691ms<br>最快：17.781µs | 平均：25.424µs<br>最慢：273.137µs<br>最快：15.358µs |

总体来看，DTVM 在平均执行时间上明显优于 Wasmtime，且最快单次执行也更快。
